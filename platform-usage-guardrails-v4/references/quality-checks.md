# Quality checks

Full checklists for Step 10 of SKILL.md.

Review every deliverable before handing it over.

### Evidence checks

- Is every number supported by a source or calculation?
- Are QUOTED, PUBLISHED, DERIVED and UNKNOWN used correctly?
- Are sources and verification dates recorded?
- Are calculations arithmetically correct?
- Have conflicting sources been identified?
- Have account-specific terms been distinguished from
  public documentation?
- Have unsupported assumptions been removed?

### Operational checks

- Is the access path correctly identified?
- Are billing units distinguished from tool calls?
- Are approval thresholds clearly labelled?
- Is the approver identified or marked as missing?
- Is the readiness status justified?
- Are stop conditions clear?
- Are retries and pagination addressed?
- Is calibration explicitly authorised before execution?
- Are behavioural rules distinguished from technical limits?

### Privacy checks

- Does the output contain confidential vendor pricing?
- Does it expose contract terms?
- Does it include licensed data?
- Does it expose credentials?
- Does it contain unpublished proprietary research?
- Are the intended recipients authorised?
- Are public and internal versions separated where needed?

If permission is uncertain, flag the material for review.

### Action accuracy checks

Never claim:

- A vendor was contacted when no contact occurred.
- A message was sent when it was only drafted.
- A file was saved when it was only generated.
- A connector was installed when it was only identified.
- A billing unit was verified when it remains unknown.
- A test was completed when only a test plan exists.
- A spending limit is enforced when it is only an instruction.

Describe completed actions accurately.

### Communication checks

- Does the team guide lead with the answer?
- Can the summary be read in under one minute?
- Is the Slack message under approximately 150 words?
- Are the next steps specific?
- Do all four deliverables agree?
- Is the language understandable to non-technical users?

Correct failures before delivery.

If a problem cannot be resolved, state the limitation.
